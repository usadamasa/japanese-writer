# sanitize-artifacts

対話で作った成果物は、放っておくと作られ方が本文に残る｡読者はその会話を見ていないので、残った痕跡は意味のない一文として読まれる｡本スキルはその痕跡を検出して、成果物の設計へ畳み込む｡

痕跡には 2 つの源がある｡制作の経緯そのもの (誰に何を言われて書いたか) と、途中で捨てた案 (何を書かないことにしたか)｡後者は「ピンクの象」節で扱う｡

## 核となる判断

会話は制作コンテキストであって、成果物の内容ではない｡本文に残すかどうか迷った記述は、次の 3 つのどれかに分類する｡

| 分類 | 例 | 扱い |
|----|----|----|
| 1. 読者が実際に必要とする内容 | 手順・判断・根拠・前提 | 本文に書く |
| 2. 成果物に影響すべきだが見えてはいけない制作上の指示 | 「初心者向けに」「CLI は避けて」「もっと短く」 | 構成・語彙・粒度・既定値・例の選び方へ畳み込む |
| 3. 会話の残骸 | 「ご指示のとおり」「前回の版と異なり」 | 消す |

難所は分類 2｡指示を本文に書き写すと、指示が守られたことの証明が読者に向かって並ぶ｡指示は結果として現れるべきで、宣言として現れてはいけない｡

## 検出対象

日本語で頻出する漏出のパターン｡

| 漏出の型 | 実際に出る形 |
|----|----|
| 依頼への応答 | 「ご要望に従い」「ご指示のとおり」「今回の依頼では」 |
| 修正の履歴 | 「前回の版と異なり」「〜に変更した」「指摘を踏まえて」 |
| 制約の宣言 | 「本手順では Git を使わない」「〜という制約があるため」 |
| 回避した手段の供養 | 「〜も検討したが採用しない」(判断記録が成果物でない文書で) |
| 会話そのものへの言及 | 「ここまでの議論では」「プロンプトにあるとおり」 |
| 節が存在する理由の説明 | 「この節は〜のために追加した」「要件を満たすため」 |
| 方針転換の経緯注記 | 「以前は X だったが現在は不要」 |
| 削除跡の申告 | 「〜は削除しました」「〜は省略しました」「〜は記載していません」 |
| 不在の宣言 | 「〜については触れません」「〜は使用していません」 |
| 調査手段の限界の申告 | 「この API からは取得できない」「user token では取れない」(参照用の一覧・台帳で) |

最後の行が特に残りやすい｡設定ファイルや doc を書き換えたとき、変更前の状態を書き残したくなる｡書かない｡doc には現在の状態だけを書く｡

これは doc に限らない｡commit message と PR 本文でも、変更前の状態の再現は差分が担う｡「ローカルでは〜だった」「以前の実装は〜」を書き足さない｡書くのは、変えた理由と、差分からは読み取れない判断だけ｡

**機械的に消さない**｡ADR の `Alternatives considered` のように、検討して捨てた案の記録が成果物の本体である文書もある｡読者がその情報を必要とするかだけで判断する｡

## 却下した案の扱い (ピンクの象)

「象のことを考えるな」と言われると象が浮かぶ｡却下された案も同じで、会話に残っている限り出力へ滲む｡修正を重ねた会話ほど濃く出る｡

滲み方は 2 つある｡捨てた案の語が本文に残る形と、捨てたこと自体が本文に現れる形｡後者が厄介で、消した跡と言い訳だけが読者に届く｡

到達点は「消した跡も言い訳も無い成果物」であって「禁止語を伏せた成果物」ではない｡

### 入力を 2 つに分ける

作り直しに入る前に、手元の情報を分ける｡混ざったまま生成すると必ず漏れる｡

| 区分 | 中身 | 生成への渡し方 |
|----|----|----|
| 現在の状態 | 最新の確定内容 | これだけを入力にする |
| 変更履歴 | 却下・削除・訂正・禁止された項目 | 生成には渡さない｡点検にだけ使う |
| 見せる例外 | 法定表示や安全表示など、消してはいけないもの | 現在の状態に含める |

### 肯定形のブリーフを組む

「X を出すな」という形の指示を生成へ渡さない｡X を名指しした時点で X が入力になる｡

> 悪い: 旧プラン名には触れない｡赤系の配色は使わない｡
>
> 良い: 現行プラン名だけで説明する｡配色は寒色でまとめる｡

現在の状態を肯定形で書き切ったものだけを渡す｡書き切れないなら、それは現在の状態がまだ決まっていない｡

### 白紙から作り直す

既存の出力から該当箇所を削って繋がない｡削った跡は文の呼吸に残り、前後の接続が不自然になる｡肯定形のブリーフを入力にして、その節をまるごと書き直す｡

### 5 層で点検する

上の層ほど気付きやすく、下の層ほど見落としやすい｡

| 層 | 見るもの |
|----|----|
| 逐語 | 却下された語がそのまま残っていないか |
| 意味 | 言い換え・上位語・頭文字で同じものを指していないか |
| 理由 | 消したこと自体への言及が残っていないか (「〜は割愛」「〜は対象外とした」) |
| 注意配分 | 却下した論点に不自然に紙面が割かれていないか｡打ち消しのために長く書いていないか |
| 視覚 | 図・表・見出し・ラベル・ファイル名・alt テキストに残っていないか |

### 直し方は破棄と再生成

点検に落ちたら、語を差し替えて通そうとしない｡通ったように見えても、同じものが別の言い方で残る｡落ちた節を捨てて、肯定形のブリーフから作り直す｡

### 文章以外の成果物

| 成果物の種類 | 起きること |
|----|----|
| 画像・動画の生成プロンプト | 却下した要素を negative prompt へ列挙してしまう｡列挙するほど、その要素が構図に効く |
| 動画 | 映像を差し替えても、旧案の台詞・効果音・テロップが残る |
| UI | 廃止した機能名がラベルの空欄・無効化ボタン・空の設定項目として残る |
| 最終サマリ | 本文から消した案が、まとめだけに生き残る |

### 限界

- 発火は意味の判定であって決定論ではない｡言い換えの検出は取りこぼす｡
- 却下された案はコンテキストから物理的に消えない｡本スキルは出力側で止める仕掛けであって、入力を消す仕掛けではない｡
- 描画済みのピクセルやフレームは確認していない｡確認していないものを確認したように書かない ([[japanese-tech-writing]] Phase 2.16)｡

## 意図伝達のための例は持ち込まない

依頼者が挙げた例は、たいてい成果物の材料ではなく診断材料｡例からは次を読み取り、例そのものは本文に入れない｡

- 想定読者
- 抽象度
- 語り口
- 避けるべき言い回し

例をそのまま本文へ運ぶと、たまたま挙がった一例が成果物の主題にすり替わる｡

## 制約は設計へ畳み込む

制約は本文で宣言せず、制約を満たした形だけを書く｡

> 悪い: この手順書では Git や Homebrew を使いません｡
>
> 良い: プロジェクトフォルダを Google Drive で共有する｡

| 制作時の指示 | 成果物での現れ方 |
|----|----|
| 「難しい用語を使わない」 | 平易な語を使う (使わない宣言はしない) |
| 「CLI のブラックボックスを避ける」 | 各手順で何が起きるかを書く |
| 「初心者向けに」 | 定義・手順の刻み・例の密度で表す |
| 「X には触れない」 | X を書かない (触れない旨も書かない) |

これは [[japanese-tech-writing]] の `references/cognitive-rhythm.md` 8 節「道具は宣言せず実装する」と同型｡向こうは文章技法の術語の漏出、本スキルは制作過程の漏出を扱う｡

## 点検チェックリスト

書き上げた直後に上から見る｡

1. 会話を見ていない読者が読んで、不自然な一文がないか
2. なぜこう書いたかを説明している文がないか
3. 使わなかった道具・避けた手段・制約への言及が残っていないか
4. 依頼者が挙げた例を、そのまま成果物の題材にしていないか
5. 複数回の修正の継ぎ接ぎが見えていないか (語り口の断層・重複した節)
6. 用語と前提が全体で一貫しているか
7. 見出しと注記が、制作者ではなく読者に向いているか
8. 断り書きが、読者に本当に必要な分だけか
9. 変更前の状態や経緯が本文に残っていないか
10. 全体が一つの声で書かれているか
11. 却下した案が 5 層のどこかに残っていないか (逐語・意味・理由・注意配分・視覚)
12. 消したこと自体を申告している文がないか

## 直し方

説明を足すのではなく、書き換える｡

漏出した文を注記で正当化して残すのは解決ではない｡文を消すか、制約を満たした記述に置き換えるかのどちらかを取る｡技術的な正しさ、成果物の目的、読者に必要な要件は保ったまま、痕跡だけを落とす｡

## 出力の作法

本スキルを単体で呼ばれたときは、修正後の成果物そのものを出す｡

「メタ指示を削除しました」「サニタイズ版です」のような前置きを付けない｡変更点の要約も併せて求められたときは、成果物を先、要約を後に置く｡

[[proofread]] の一部として走るときはこの限りでない｡proofreader subagent の仕事は Tier 分類した検出結果を return することで、成果物そのものを出力しない｡

## 適用しない文書の種類

| 文書の種類 | 理由 |
|----|----|
| 議事録・対話ログ・作業記録 | 会話の記録そのものが成果物 |
| ADR の `Alternatives considered` | 捨てた案の記録が成果物の本体 |
| 変更履歴・リリースノート・差分レビュー | 変更前の状態を示すことが目的 |
| A/B の比較・監査記録・障害の事後分析 | 採らなかった側と経緯が読者の必要とする情報 |
| 法令・契約・広告表示・安全・医療・アレルギー・アクセシビリティ | 表示義務があり、消すと成果物が不正になる |
| 不在の明示を求められた文書 | 「何を含まないか」の宣言が依頼された内容そのもの |

優先順位は上から順に強い｡表示義務のあるものが最優先で、次に読者が求めた内容、最後に最新の確定状態｡痕跡を消す都合が表示義務を上回ることはない｡

## 到達点

読者が、成果物からプロンプトの履歴・内部の制約・修正のやりとりを再構成できない状態｡意図して設計され、一つの声で書かれ、読者の側の言葉で書かれていると読める状態｡
