# 認知リズムの規範 (Cognitive Rhythm)

> このファイルは [[japanese-tech-writing]] Phase 1.2 で判定した文書の種類が
> **書籍の章 / blog 長文 / 長文ノート** のときに参照する｡
> **ADR / Design Doc / Stock 文書** では「1. 開幕の緊張」と
> 「4. 状況 vs 文書テスト」だけを弱適用する｡
> **Slack / Flow 文書 / 議事録** では適用しない｡

現行の Phase 2 (執筆) と Phase 3 (self-check) は、論証の骨格と表面の整形が主戦場である｡本規範は別レイヤーを扱う｡**読者が最後まで読み進めるための緊張とリズム**を設計する｡

減点法 (冗長排除・LLM 口調禁止) では、読者が読み止めない状態は作れても、読み続けたくなる状態は作れない｡加点法として本規範を重ねる｡

## 適用の基本原則

- **道具は宣言せず実装する**｡「ここで半分だけ答えを置く」と本文に書かない｡実際に半分だけ置く｡
- **短文バイアスをかけない**｡必要な文脈を切って短くしない (Phase 2.5 の 60 字目安と衝突するが、書籍章では本規範を優先する)｡
- **リズムの材料は状況から取る**｡文章の見え方についてのメタ言及からは取らない｡

---

## 1. 開幕の緊張 (opening tension)

冒頭数文で、未解決の緊張を 1 個作る｡

**許される開幕型**:

- **読者の実感の言い直し**: 読者が抱えているが言語化できていない違和感を、書き手の言葉で先に置く｡
- **直接の問い + 短い先答え**: 「なぜ〜なのか｡答えは〜だが、そのままでは足りない｡」
- **信じられている一般命題の検証宣言**: 「一般に〜と言われる｡本章ではこれを疑う｡」
- **書き手の仮説を後で事実で裏切る**: 冒頭で確信を置き、本文で反例を出す｡

**禁止する開幕型**:

- **無姿勢の agenda 表**: 「本章では A、B、C を扱う」｡姿勢のない目次は緊張を作らない｡
- **「〜が重要である」から始める**: 主張の内容を書かず、主張の重要性だけを予告する｡
- **背景の羅列**: 読者がまだ問いを持っていない段階で背景を積み上げる｡

## 2. 節開幕の設計 (section opening)

節の冒頭で「本節では〜を扱う」と宣言しない｡代わりに次のいずれかで開く｡

- **前節の余韻を問い直す**: 前節で残した違和感を、読者の口から出そうな問いの形で書き直す｡
- **読者の自然な反問**: 「では〜はどうか」を書き手が先回りする｡
- **書き手の告白**: 「ここまで〜と書いてきたが、実は〜という懸念が残っている」｡
- **命名としての理論導入**: 理論・術語を「答え」として先に置かず、名前のない違和感を作ってから「これを〜と呼ぶ」の形で名を与える｡

**bridge (橋渡し) の位置**: 節と節の橋渡しは、前節の末尾ではなく **次節の頭** に置く｡前節の末尾で「次節では〜」と予告すると、前節の緊張がそこで解消されて次節へ引かない｡

## 3. 認知モードの交替 (cognitive mode alternation)

文章の疲労は情報密度ではなく、**認知モードの均質さ** から来る｡以下 4 モードを意図的に切り替える｡

| モード | 読者に要求する働き | 典型的な文型 |
|--------|--------------------|--------------|
| 観察 | 事実を受け取る | 「〜が起きた｡データは〜を示す｡」 |
| ためらい | 判断を保留する | 「〜のように見えるが、確信は持てない｡」 |
| 断定 | 命題を受け入れる | 「したがって〜である｡」 |
| 再観察 | 断定を検証する場面へ戻る | 「もう一度データを見ると〜」 |

濃い断定が 3 段落続いたら、次は観察かためらいを 1 段落挟む｡

## 4. 状況 vs 文書テスト (situation vs document test)

書いた文を 1 文ずつ次のテストにかける｡

> その文は **状況** を進めるか｡それとも **文書** を進めるだけか｡
>
> - 世界の出来事・データ・話し手の判断状態を更新する → **状況を進める**｡ 残す｡
> - 章の見え方・次に何を書くか・書かない予告 → **文書を進めるだけ**｡ 削除｡

**削除対象の典型**:

- 「ここまで概念の説明が続いたので、例に戻ろう」
- 「本章の主題は X ではなく Y である」
- 「詳しくは後述する」
- 「以下では〜を扱う」
- 「まずは〜から見ていく」

**例外として残してよい形は 4 種類だけ**:

1. **反論処理**: 具体的な誤読を引用して否定する場合｡「〜と読めるかもしれないが、〜」
2. **問いの立てと回収**: 問いそのものと、その回収文｡それ以外の予告は不可｡
3. **境界での読者への要請**: 章冒頭/章末で「〜という枠組みを受け入れてほしい」など｡本文中では使わない｡
4. **例の開閉フレーム**: 「〜という場面を考える｡……ここまでを例とする｡」

## 5. 文のビート (sentence beat)

一文の長さを、以下のパターンで意図的に変える｡

- **立てる → 流す → 止める**: 短い断定 → 中程度の説明 → 短い切断｡
- **断定 → ためらい**: 「〜である｡ただし本当にそうか｡」
- **転回点の型**: 譲歩 → 逆接 → 短い休止｡「確かに〜｡しかし〜｡ここで一度立ち止まる｡」

ためらいは弱さではなく **仕掛け** である｡「うまく行っているはずだ」を先に置き、後で事実に裏切らせる｡

短文バイアスに気をつける｡文脈が必要なら長く書く｡ただし節が 3 個以上並んだら分割を検討する (Phase 2.5 の閾値と整合)｡

## 6. 段落密度の波 (paragraph density wave)

濃い段落 2〜3 個の後に、薄い段落を 1 個挿む｡

- **濃い段落**: 具体・データ・厳密な論証｡
- **薄い段落**: 意味づけ・遠くから見る評価・箇条書きによる息継ぎ｡

意味づけの段落は、直前の具体を要約しない (それは Phase 2.13 冗長排除に抵触)｡具体からは離れた高さで、その具体が何のために出てきたかを別の言葉で置き直す｡

箇条書きは「息継ぎ」として機能する｡ただし着地は §7 に従う｡

## 7. 列挙の着地 (enumeration landing)

箇条書き・表・番号付きリストの各項目は、宙に浮かせない｡読者がすでに持っている具体シーンに着地させる｡

**着地の型を変える** (単調を避けるため):

- **犯人特定型**: 「〜が問題である｡だから〜が起きた｡」
- **個人的認識型**: 「著者は最初〜と誤解していた｡実際は〜である｡」
- **事実対応型**: 「〜という指摘がある｡実際、〜という事故が起きている｡」
- **将来の諦念型**: 「〜は解けない｡少なくとも短期には｡」

同じ着地型を 3 項目以上連続させない｡

**表の場合**: 表の直後に、表の 1 セルを取り出して具体場面と結ぶ 1〜2 文を置く｡「たとえば新しく入った開発者の初日を思い出せば、環境変数の設定に彼らは何も苦労していない｡起動スクリプトが引き受けているからだ｡」

## 8. 道具は宣言せず実装する (devices realized, not declared)

本規範自身の術語 (緊張・回収・半分だけ・認知モード・着地) を、本文に **持ち込まない**｡道具は姿を消すからこそ効く｡

**悪い例**:

- 「ここで半分だけ答えを置く｡」
- 「認知モードを切り替えるために、次段落は薄くする｡」
- 「読者の緊張を維持するため、この問いは次章まで回収しない｡」

**良い例** (実装のみで、宣言なし):

- 「答えは〜である｡ただし、これが成立するのは〜のときに限られる｡」← 半分だけ答えるを実装している
- (濃い段落 3 個の後に、意味づけの短い段落を置く) ← 段落密度の波を実装している

## 9. 診断処方箋 (diagnostic prescriptions)

推敲時に感じる 6 症状と、対応する処方｡

| 症状 | 診断 | 処方 |
|------|------|------|
| どの段落も同じ手触りで疲れる | 文のビートがない | §5 を適用｡濃い断定の連続に短いためらいを 1 文挿む |
| 正しいが読み進めたくならない | 開幕の緊張がない | §1 を適用｡冒頭 3 文を書き直し、未解決を 1 個作る |
| 理論の節に入ると温度が下がる | 理論を答えとして置いている | §2 の「命名としての理論導入」を適用｡命名の前に違和感を作る |
| slack sentences を消したのに緩んで見える | slack が文書側だった | §4 を再適用｡状況側の slack (判断保留・仮定・感情のニュアンス) に書き換える |
| 章末が説教くさい | 抽象で終えている | §7 の着地を末尾に適用｡読者が持つ具体に落とし、1 個の緊張を残す |
| 冒頭が官僚的 | 無姿勢の agenda | §1 の「読者の実感の言い直し」または「書き手の仮説」で書き直す |

## 10. 推敲手順 (inspection procedure)

Phase 3 self-check 項目 8 として次を回す｡機械では拾えない項目に絞る｡

1. **topic テスト** — 各段落の 1 文目と単独短文だけを拾い読みして、主旨と流れが追えるか (Phase 3 項目 4 と重複するが、リズム観点で再確認する)
2. **漏出テスト** — 本規範の術語 (緊張・回収・半分・認知モード・着地・ためらい・道具・状況 vs 文書) が本文に流出していないか｡grep で検索する
3. **緊張元帳** — 全ての問い・仮定・約束を列挙し、それぞれの回収位置に印を付ける｡末尾に **ちょうど 1 個** の未回収を残す
4. **ビート点検** — 3 個以上の長い断定が連続する箇所を探し、短い足場かためらいを挿む
5. **境界点検** — 二人称呼びかけと読者への要請が、章の冒頭/末尾以外に混入していないか

## 文書の種類別強度の調整

Phase 1.2 文書の種類別マトリクスに **認知リズム** 列を追加した｡本規範の適用強度は以下:

| 文書の種類 | 認知リズムの強度 | 適用範囲 |
|----|------------------|----------|
| Slack / times | × | 適用しない (短文で緊張設計は不要) |
| Flow 文書 / 議事録 | × | 適用しない |
| ADR | △ | §1 開幕の緊張 + §4 状況 vs 文書テストのみ |
| Design Doc | △ | 同上 |
| Stock 文書 | △ | 同上 |
| blog / 長文記事 | ○ | 本規範を全面適用｡ただし §3 認知モードは軽めでよい |
| 長文ノート (>3000 字) | ○ | 同上 |
| 書籍の章 | ◎ | 本規範を全面適用｡§3 認知モードの交替まで作り込む |
